# Boot loader
- checks operating systems in the hard disks
- bootloader can only be a small program (due to architecture limitations)
- for GUI and other computations, create an artificial bootloader. The first bootloader passes the control to this second which is a sort of a operating system and a bootloader at the same time. (second stage bootloader)
- bootloader hands over to OS when it finishes 
- usually works in real mode

# Intel/PC startup
- execution starts at 0xffffffff0, BIOs should be located at this location in the memory, otherwise the PC won't start
- works in real mode (two modes: real or protected)
- need to do some tasks to go from real mode to protected mode
- cpu jump to protected mode smth

# Booting Windows:
- BIOs doesnt know file system, OS reads the file system
- MBR Master boot record = Block 0 of disk (512 bytes) 1 in each hard disk. MBR not correct, operating system won't load. Fix MBR instead of reinstalling operating system
- volume boot record (boot record in each partition of the hard disk). MBR goes and checks each partition's volume boot record.
- volume boot record contains information regarding from the where the operating system needs to be booted
- linux's MBR includes windows if its information is inside of the partition's VBR. Window's MBR disregards others

# Booting other systmes on a PC:
- talking about linux bootloader
- MBR contains GRUB stage 1
- stage 1 loads stage 2
- stage 2 very powerful, can disable hardware etc and then load the OS

# PCs and UEFI:
~2005: unified extensible firmware interface
- BIOs loads the operating system directly by checking the UEFI loaders

# EFI Booting
- no need for MBR code
- reads GPT (protection setup)
- EFI understands the FAT file system
- EFI replaces traditional BIOs

# Hypervisors
- virtual machine manager
- boot virtual machine directly from EFI


Hardware -> VMM (xen) -> VM -> OS -> apps
